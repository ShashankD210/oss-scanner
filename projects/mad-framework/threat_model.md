# Threat model — Mad Framework (madbuilder/framework)

## What this project does and where untrusted input enters
Mad Framework is the open-source Laravel runtime behind apps generated by MadBuilder (a low-code platform):
admin panels, ERPs, point of sale, multi-tenant SaaS. Screens are PHP "controls" that render `<mad-*>` Blade
components (forms, grids, kanban, calendar, charts, PDF documents) and receive AJAX actions from the browser
without a build step. The package also ships the IAM/permission engine, multi-tenancy and business units, a REST
layer, an MCP server and an AI copilot. Apps run in production with real business and personal data.

Untrusted input enters through:
- **Screen requests** (`src/mad/http/Controllers/MadAppController.php`, routes from `src/mad/routing/MadRoutes.php`):
  `/app/<screen>/<method>` calls a public method of a control. Callers are authenticated users limited by
  per-action permissions (`src/mad/security/`: `PermissionGate`, `ActionGuard`, `MadPermission*`). **A user is
  untrusted beyond the screens and actions granted to them.** Calling a method, reading a record or acting on a
  row the user has no permission for is a vulnerability.
- **Form submissions and data actions** (`src/mad/form/`, `src/mad/service/MadRecordService.php`, `MadDb*Service`):
  save/delete of records, master-detail rows, field lists, combos and searches. Combo/search endpoints receive
  signed tokens that name the model, columns and filters; forging or reusing a token to read other tables or
  columns is in scope.
- **Grid parameters** (`src/mad/grid/`, `src/mad/filters/`): filters, custom filters, order-by, grouping,
  totals, pagination and export (CSV/XLSX/PDF). Column names and operators come from the request and end up in
  SQL. SQL injection, reading columns not shown on the screen, and bypassing row scoping are high/critical.
- **Multi-tenancy and business units**: records are scoped by tenant/unit. Reading or writing another tenant's
  or another unit's data is critical.
- **File handling** (`src/mad/http/Controllers/Mad*Download*`, `MadBlobDownloadController`,
  `MadPublicFileController`, `src/mad/service/MadPublicUpload.php`): uploads, downloads and public files. Path
  traversal, serving files of another record/tenant, and upload of executable content are in scope.
- **Public pages** (`src/mad/site/`): public website pages and their POST/wire endpoints run without login.
- **REST** (`src/mad/rest/`): API resources and the signed remote-database driver (`RestDriver*`, with a
  read-only guard and SQL scanner). Bypassing the signature, the read-only guard or the SQL scanner is critical.
- **Incoming webhooks** (`src/mad/Webhook/`): signature verification and scope of what a webhook may write.
- **MCP server** (`src/mad/mcp/`): tools exposed to external AI clients with per-user grants. A token or user must
  not reach data or tools beyond its grants.
- **AI copilot** (`src/mad/ai/`): prompts and tool calls on behalf of the logged user. Prompt injection from
  stored data that makes the copilot act beyond the user's permissions is in scope.
- **Rendering**: Blade components escape output; stored/reflected XSS through component props, grid cells,
  PDF/document templates (dompdf) and markdown (`league/commonmark`) is in scope. SSRF through PDF remote
  resources or server-side fetches (`MadCepService`, `MadCnpjService`, `MadBuilderServiceClient`) is in scope.
- **Installer** (`src/mad/install/`): must not be usable once the app is installed.

## Components that matter most / least
- Most: `security/`, `http/`, `Web/` (session, CSRF, auth helpers), `form/`, `grid/`, `filters/`, `service/`,
  `database/`, `rest/`, `Webhook/`, `mcp/`, tenancy/unit scoping wherever it appears.
- Less: `chart/`, `calendar/`, `orgchart/`, `sheet/`, `pdv/` rendering (still in scope for XSS and authorization),
  `console/` (artisan commands run by operators), `assets/` (front-end JS/CSS; DOM XSS is in scope).
- Out of scope: bugs that live entirely in third-party dependencies (Laravel, dompdf, openspout, etc.) unless the
  framework makes them reachable; the host application at `/app` (a stock Laravel skeleton used only to load the
  package); denial of service that needs an authenticated admin.

## How to exercise it
- Package source: `/src` (PSR-4 namespaces `Mad\*` under `src/mad/`). Host app: `/app`, Laravel 13, SQLite
  database at `/app/database/database.sqlite`, package installed at `/app/vendor/madbuilder/framework` (symlink to
  `/src`).
- `cd /app && php artisan tinker` or a PHP script that boots `/app/bootstrap/app.php` gives the full container.
  `cd /app && php -S 127.0.0.1:8000 -t public public/index.php &` serves HTTP. With no screens installed, the
  package already registers these routes (`php artisan route:list`): `POST app/_mad-wire` (screen actions),
  `POST public/_mad-wire` (public site actions, no login), `GET app/_mad-blob`, `GET app/_mad-download`,
  `GET app/_mad-grid-export`, `GET arquivos/{path}` (public files), `POST api/webhooks/{slug}/{key?}`,
  `GET robots.txt`, `GET sitemap.xml`. Screen routes `/app/<screen>/<method>` appear for each class under
  `/app/app/control/`.
- Screens are classes under `/app/app/control/` (create the directory). A minimal control extending the
  framework's page/form classes, plus `php artisan route:list`, is the quickest way to reproduce an HTTP issue.
- The host app's PHPUnit (`cd /app && php artisan test`) can run feature tests written against the package.
  A PHPUnit test or a short PHP script is the preferred reproducer.

## How we rate severity
- Critical: unauthenticated RCE, SQL injection, authentication bypass, cross-tenant read/write, forging signed
  tokens or REST driver signatures.
- High: authenticated RCE or SQL injection; privilege escalation (a user reaching actions, screens, records or
  columns outside their permissions); path traversal that reads/writes outside the upload area; stored XSS that
  runs in another user's session; SSRF to internal addresses.
- Medium: reflected XSS, CSRF on state-changing actions, information disclosure of non-sensitive data, open
  redirect.
- Low: issues that need an admin to attack themselves, missing hardening without a concrete exploit.

## Reports
Please include the framework version (`/src/VERSION`), the affected file/method, a reproducer and a proposed patch.
Reports may be written in English or Portuguese.
